# Штаб

> Слой правды. Здесь лежит то, что верно про вашу систему, и отсюда агент начинает работу.

Штаб это точка входа и карта: кто вы, какие отделы есть рядом, где искать правду и где живёт очередь. Задачи и рабочие материалы лежат в отделах.

## Что в папке

| Файл | Слой | Зачем он здесь |
|---|---|---|
| [`AGENTS.md`](./AGENTS.md) | правды | Правила агента, границы, карта отделов и таблица "где живёт правда" |
| [`CLAUDE.md`](./CLAUDE.md) | правды | Подключает те же правила для Claude Code |
| [`me.md`](./me.md) | правды | Кто владелец штаба и что агенту нужно про него знать |
| [`tasks.md`](./tasks.md) | операционный | Точка старта агента и задачи на сегодня |
| [`skills/`](./skills/) | правды | Скиллы штаба и правило, как добавить свой |

## Порядок действий

1. Скопируйте папку к себе и назовите её `HQ` или как вам удобнее.
2. Заполните `me.md`. Это единственный файл, который пишется целиком вручную.
3. В `AGENTS.md` замените места `<...>` и удалите строки, которые к вам не относятся.
4. Откройте агента из этой папки и скажите: "прочитай `AGENTS.md` и расскажи, что здесь происходит".
5. Заведите первый отдел из [`../department/`](../department/) рядом со штабом, не внутри.

## Что появится позже само

Эти файлы создают скиллы, когда им есть что записать. Заранее их создавать не нужно: пустой файл выглядит как правда, правдой при этом не являясь.

| Появится | Когда | Кто создаёт |
|---|---|---|
| `tasks/` с планами недели и дня | Когда одного списка станет мало | планирование |
| `retros/` | После первого недельного ретро | ретро |
| `decisions.md` | Когда появится первое решение, о котором придётся вспомнить | решенческий скилл |
| `CONTEXT.md` | Когда термины начнут расходиться | domain-modeling |
| `okr.md`, `products.md`, `people.md` | Когда будет что в них писать | вручную |

## Три уровня задач

Штаб стартует с первого уровня и растёт по мере надобности.

1. **Один файл.** `tasks.md` держит задачи на сегодня в одном месте.
2. **Локальная система.** День, длительные задачи и лог разъезжаются по отдельным файлам внутри рабочей папки.
3. **Трекер.** Состояние длительных задач переезжает в GitHub Issues, а день остаётся коротким списком со ссылками.

Переходите на следующий уровень только когда предыдущий начал мешать.
