# Задачи отдела

> Операционный слой. Здесь лежит контракт: где живёт состояние задачи, какие бывают статусы и как отдел переезжает в трекер. Сами задачи появляются по мере работы.

Каждая активная локальная задача хранится в отдельном Markdown-файле по шаблону [`_template.md`](_template.md).

## Активный режим

- Источник активных задач: локальные файлы
- Репозиторий GitHub:
- Дата перехода:

Когда отдел переходит в трекер, этот блок меняется один раз на `GitHub Issues`, URL репозитория и дату перехода. Скиллы отдела читают активные задачи из указанного здесь источника.

## Имена файлов

```text
ГГГГ-ММ-ДД-короткое-название.md
```

Пример:

```text
2026-07-14-подготовить-пост.md
```

## Состояния

- `новая` — результат сформулирован, работа не началась;
- `в работе` — выполняется следующий шаг;
- `на приёмке` — результат готов к решению founder;
- `завершена` — результат принят, ссылка и итог записаны;
- `заблокирована` — указан конкретный блокер и следующий способ снять его;
- `снята` — работа осознанно прекращена, причина записана в итог, поле `Завершена` содержит дату решения.

## Локальный и GitHub-режим

В режиме `локальные файлы` источником состояния каждой активной задачи является отдельный Markdown-файл.

Переход разрешён только после проверки всех локальных записей: в момент переключения не должно остаться ни одной другой активной локальной задачи. Проще всего переходить, когда активная задача одна.

После чистого переноса в режим `GitHub Issues`:

1. Issue становится новым источником состояния активной задачи;
2. все остальные локальные задачи уже завершены, сняты или тоже перенесены;
3. блок «Активный режим» получает URL репозитория и дату перехода;
4. `README.md` начинает ссылаться на Issue;
5. локальный активный файл удаляется после проверки Issue;
6. `daily`, `retro` и `planning` читают активные задачи из GitHub Issues текущего репозитория;
7. одна задача не редактируется одновременно в файле и в Issue.

Шаблон `_template.md` и закрытая локальная история не переносятся автоматически. Ретро недели перехода читает локальные записи со статусом `завершена` или `снята` до даты перехода включительно и GitHub Issues с даты перехода.

## Что не хранить здесь

- сам рабочий результат, если ему принадлежит другая система;
- полный лог чата;
- постоянные правила отдела;
- независимую копию состояния из GitHub.
